## 1. 目标与边界

### 1.1 四维框架

| 维度 | 用户问题 | 舰队页 | 单机「未来」Tab |
|------|----------|--------|-----------------|
| **一、核心风险** | 要不要管？ | 主视觉（HI、24h PoF、RUL 区间） | 结论卡置顶 |
| **二、故障归因** | 为什么？ | 仅 Top1 标签 | Top3 贡献、劣化加速度、残差 |
| **三、可信度** | 准不准？ | 数据无效标记、置信度徽章 | CI、覆盖度、预测暂停 |
| **四、业务决策** | 怎么排产/汇报？ | 建议检修日、预警/报警分级 | 成本权衡、不处理后果、案例 |

### 1.2 预警 vs 报警（统一规则）

| 级别 | 条件（Demo 规则） | 触达建议 | 平台行为 |
|------|-------------------|----------|----------|
| **normal** | HI≥70 且 RUL>30 且 7d PoF<20% | — | 常规巡检 |
| **warning** | HI 40～69 或 7d PoF 20%～49% 或 RUL 7～30 天 | 邮件/站内 | 进关注清单 |
| **alarm** | RUL<7 或 24h PoF≥30% 或 HI<40 | 短信/电话 | 建议工单（高置信时） |
| **paused** | 采集离线或无近期采样 | — | **预测暂停**，不展示硬数字 |

低置信度（`confidence=low`）的 alarm 降级展示为「建议人工复核」，不触发自动工单（Phase 1 仅 UI 标记）。

## 2. 数据模型（`catalog.devices[].future` 扩展）

### 2.1 已有字段（保留）

`risk_24h` / `risk_72h` / `risk_7d`、`likely_fault`、`fault_type_probs`、`rul_days`、`rul_ci`、`avoid`、`contingency`

### 2.2 Phase 1 新增（API 投影计算，不强制改 catalog）

| 字段 | 类型 | 说明 |
|------|------|------|
| `health_index` | 0～100 | 派生：`clamp(100 - risk_7d, 0, 100)` |
| `health_band` | green/yellow/red | ≥70 / 40～69 / <40 |
| `alert_level` | normal/warning/alarm/paused | 见上表 |
| `confidence` | low/medium/high | 由 `rul_ci` 宽度派生 |
| `data_valid` | bool | `comm_status=online` 且有 `last_sample_at` |
| `data_valid_reason` | string? | 无效原因 |
| `prediction_paused` | bool | 数据无效时为 true |
| `maintain_by` | ISO date | 建议检修截止日期 |
| `rul_range_label` | string | 如 `100～140 天` |
| `model_coverage` | string[] | 模型覆盖故障类型 |

### 2.3 Phase 2 新增（catalog + 生成脚本）

| 字段 | 说明 |
|------|------|
| `attribution_top3` | `[{metric, contribution_pct, text}]` 规则/SHAP |
| `degradation_ratio` | 相对上周劣化倍数 |
| `residual_score` | 残差异常分 0～100 |

### 2.4 Phase 3 新增

| 字段 | 说明 |
|------|------|
| `cost_if_wait` / `cost_if_fail` | 停机成本估算 |
| `threshold_profile` | aggressive/balanced/conservative |
| `similar_cases` | 历史相近工况处理方案 |
| `backtest_saving` | 回溯仿真节省金额（案例） |

## 5. API 约定

- 所有未来指标经 `_project_future_metrics(device)` 投影，**禁止各端点自写第二套算法**。
- Phase 3 决策字段：`cost_if_wait` / `cost_if_fail` / `threshold_options` / `similar_cases` / `backtest_*`。
- 列表接口只返回决策摘要（成本、可少损），详情返回完整案例列表。

## 6. 验收标准

### Phase 1
1. 舰队表统一 RUL **区间文案**；24h PoF 在 7d 之前。
2. 离线设备 **预测暂停**。
3. 单机未来 Tab 四块齐全；`tsc` 通过。

### Phase 2
1. Top3 归因 + 劣化周趋势 + 残差可见。
2. 舰队「主因」列有文案。

### Phase 3
1. 单机页可见计划干预 vs 突发故障成本差额。
2. 可切换「更保守 / 平衡 / 更激进」策略说明。
3. 相近工况案例 ≥2；舰队叙事含回溯故事。
4. `tsc` 通过。
