## 0. 目标与非目标

### 目标

1. **通用能力进平台壳**，**每个业务一个清晰模块边界**（目录 + 注册表）。
2. **售卖两种模式都要能落地**（见 §1，本计划的主需求）：
   - **模式 A · 代码交付本地部署**：只复制客户买的模块 + 平台壳，不相干业务代码不给。
   - **模式 B · 远程托管访问控制**：代码在我们侧；客户只能打开约定页面、只能调约定接口。
3. **布局可配**：两种模式下都可能不要我们的顶栏 / 左侧导航（嵌进客户自己的门户）。
4. **渐进演进**：先同仓模块化打好边界，再分别强化「可拷贝裁剪」与「远程授权」；现网交付分支可继续用。

### 非目标（本计划不做）

- 不把业务拆成多个微服务（除非模式 B 后期流量要求再议）。
- 不重写排产 / 设备分析业务逻辑；只迁目录与接入 / 授权方式。
- 不在本阶段做面向客户的自助购买商城；授权可由我们后台或配置发放。

## 1. 两种售卖模式（主需求）

```
                    ┌──────────────────────────┐
                    │  客户购买了某些 module    │
                    └────────────┬─────────────┘
                                 │
              ┌──────────────────┴──────────────────┐
              ▼                                      ▼
   ┌─────────────────────┐              ┌─────────────────────────┐
   │ 模式 A：代码交付     │              │ 模式 B：远程托管         │
   │ 本地部署             │              │ 我们服务器               │
   ├─────────────────────┤              ├─────────────────────────┤
   │ 拷贝：platform 壳    │              │ 全量或裁剪部署在我方     │
   │      + 已购 modules │              │ 客户账号 / 租户绑定 SKU  │
   │ 不拷贝：未购 modules │              │ 页面：只能进已购路由     │
   │ 客户自建库、自运维   │              │ 接口：只能调已购 API     │
   └─────────────────────┘              └─────────────────────────┘
              │                                      │
              └──────────┬───────────────────────────┘
                         ▼
              layout_mode: full | embed
              （要不要我们的顶栏/侧栏，与卖法正交）
```

### 模式 A — 复制部分代码，客户本地部署

| 要点 | 说明 |
|------|------|
| 给什么 | `platform`（壳，必需）+ 客户购买的 `modules/*`；**未购模块目录整份不出现在交付包** |
| 不给什么 | 其他业务源码、其路由/菜单/API、相关 fixture（除非公共） |
| 怎么交 | 从模块化仓 **按 edition 导出/打包**（脚本拷贝或构建产物），不是手工从单体里捡文件 |
| 客户侧 | 自备环境本地跑；可用 `full` 整站，也可用 `embed` 嵌进他们系统 |
| 对我们的要求 | 目录边界硬：无跨模块 import，否则「少拷一个文件夹」会跑不起来 |

### 模式 B — 远程开通，限制页面与接口

| 要点 | 说明 |
|------|------|
| 给什么 | 账号 / 租户 + 已购模块清单（或更细的页面/API 白名单）；**不交未购业务源码** |
| 页面 | 前端路由守卫 + 菜单过滤：未购 path → 403/404 |
| 接口 | 后端强制校验：请求所属 module 不在租户 SKU 内 → 403；不能只靠「藏菜单」 |
| 粒度 | 一期：**按 module**（买了排产 = 该模块下页面+API）；二期可选细到 API permission 码 |
| 客户侧 | 浏览器打开我们域名，或 iframe/`embed` 进他们门户 |
| 对我们的要求 | 同一套运行实例可服务多客户时，**租户 → enabled_modules**（或 API 白名单）必须服务端生效 |

### 两种模式共用的工程前提（所以要先模块化）

无论 A 还是 B，都依赖同一套边界：

- 每个业务一个文件夹 + 注册表（路由 / 菜单 / API 同属一个 module id）
- `enabled_modules`（或等价 SKU）成为 **唯一真相**
- 模式 A：用它决定 **拷贝/打包范围**
- 模式 B：用它决定 **运行时放行范围**

## 2. 目标架构（心智模型）

```
┌─────────────────────────────────────────────┐
│  Edition / SKU（启用哪些 module）             │
│  delivery_mode: code_export | remote_hosted │
├─────────────────────────────────────────────┤
│  Platform 壳                                 │
│  auth · layout(full|embed) · menu · perm     │
│  branding · 通用 UI / 图表壳 / 文件           │
├──────────┬──────────┬───────────────────────┤
│ module A │ module B │ module C …            │
│ 排产      │ 设备分析  │ 工具箱 / 文件分析 …   │
└──────────┴──────────┴───────────────────────┘
```

**三组正交配置：**

| 维度 | 配置项 | 含义 |
|------|--------|------|
| 卖什么 | `enabled_modules` | 装 / 开哪些业务 |
| 怎么交 | `delivery_mode` | `code_export` 本地拷贝包 / `remote_hosted` 远程授权 |
| 怎么嵌 | `layout_mode` | `full` 完整壳 / `embed` 无顶栏侧栏 |

## 3. 目标目录（落地形态）

> 实施时以「迁目录 + 注册表」为主，避免一次改爆。名称可在评审时微调。

### 前端（建议）

```
frontend/src/
  platform/                 # 壳：布局、鉴权、菜单渲染、品牌、通用 hooks/kit
    layout/
    auth/
    menu/
  modules/
    scheduling/             # 页面 + 模块路由表 + 菜单声明（可选）
    equipment-analysis/
    toolbox/                # 单位换算、文件分析等工具型
    system/                 # 系统管理也可视为「平台附属模块」，默认随壳
  editions/
    default.json            # 本地/演示：全开
    sku-scheduling-local.json   # 模式 A 示例：仅排产，用于导出包
    sku-scheduling-remote.json  # 模式 B 示例：仅排产，远程租户
  App.tsx                   # 只负责：读 edition → 注册已启用模块路由
```

### 后端（建议）

```
backend/app/
  platform/                 # 或保留现有 core，明确「仅平台」
  modules/
    scheduling/
    equipment_analysis/
    toolbox/
  editions/                 # 或 settings / 租户表字段
  api/router.py             # 按 enabled_modules include_router（模式 A 包内即裁剪；模式 B 全量+守卫亦可）
```

### 约定（写进后续 CONTRIBUTING / demo-scaffold 增补）

1. 业务代码只进自己的 `modules/<name>/`，禁止业务 → 业务的跨模块 import（共享能力下沉 platform）。
2. 新菜单 / 路由 / API 由模块 **注册表** 声明，平台汇总；禁止只在全局 `App.tsx` / `seed.py` 手写漏登记。
3. 模块对外只暴露：`routes`、`menus`（或 menu seed 片段）、`api_router`、可选 `permissions`。
4. 每个 API 归属且仅归属一个 `module_id`，供模式 B 拦截与模式 A 打包清单使用。

## 4. 布局模式（embed）— 必须可配置

| `layout_mode` | 表现 | 典型客户 |
|---------------|------|----------|
| `full` | 顶栏 + 左侧导航 + 内容区（现状） | 交钥匙整站 / 模式 A 本地门户 |
| `embed` | 无侧栏、无顶栏（可保留极简安全区），只渲染业务页 | 挂进对方 OA（A/B 都可能） |
| `content_only`（可选二期） | 更裸的内容区，适合 iframe | 强嵌入 |

**配置来源（优先级建议，实施时定一种主路径 + 一种覆盖）：**

1. 租户 / 系统配置（后台可改）  
2. URL：`?embed=1` 或路径前缀 `/embed/...`（便于联调）  
3. Edition JSON 出厂默认  

**embed 时额外行为：**

- `/auth/me/menus` 可返回空或忽略侧栏渲染（入口由对方系统提供）。
- 支持 Token / SSO 透传（一期可先：已有 JWT 约定；二期正式 SSO）。
- 路由 `basename` 可配置（挂子路径，如 `/oa/ai-scheduling`）。
- 不渲染「退出到我们登录页」的硬导航；提供可选 `postMessage` / 回调（二期）。

## 5. 两种模式的技术落地

### 5.1 模式 A：导出「可拷贝的本地包」

目标：执行脚本或 CI，输入 edition，输出目录/压缩包 = `platform + enabled_modules`，**物理上没有未购模块源码**。

一期建议：

- [ ] 维护 `modules/<id>/MANIFEST`（含前端路径、后端路径、菜单 id、API 前缀）
- [ ] 脚本 `scripts/export_edition.py`（或 shell）：按 MANIFEST 复制到 `dist/export/<sku>/`
- [ ] 导出包内写死或带 `edition.json`（仅含已购模块）
- [ ] 文档：客户如何安装导出包、如何配库

二期增强：Vite/后端构建也只编进已购模块（减小体积、防漏拷）。

### 5.2 模式 B：远程「只能访问这些页 / 这些接口」

目标：客户连我们的环境；服务端按租户 SKU 强制限制。

一期建议：

- [ ] 租户或角色扩展字段：`enabled_modules: string[]`（或绑定 edition id）
- [ ] **页面**：前端不注册未购路由 + 守卫；菜单接口按 SKU 过滤
- [ ] **接口**：全局中间件根据 path/permission → `module_id`，不在 SKU 内直接 403  
  （关键：**藏菜单不够**，必须拦 API）
- [ ] 管理端（我们用）：给租户开通/关闭模块，即时生效
- [ ] 审计：拒绝访问记一笔（可选）

粒度：

| 级别 | 一期 | 二期 |
|------|------|------|
| 模块级 | ✅ 买排产 = 该模块全部页+API | — |
| 页面级 | 可选（同一 module 内再藏菜单） | 细路由白名单 |
| 接口级 | 随 module 绑定 | 单 API 白名单 / 配额 |

### 5.3 与「仅藏菜单」的区别（必须做到）

| | 只藏侧栏（现状可凑合） | 本计划模式 A / B |
|--|----------------------|------------------|
| 未购源码 | 仍在交付物里 | A：不复制；B：客户拿不到 |
| 未购 URL | 可能仍能打开 | 守卫拦截 |
| 未购 API | 可能仍能调 | B：中间件 403 |

**验收：** 该模块在「仅启用自己」下可独立演示（远程守卫 + 本地只启该模块）。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 大搬迁影响交付分支 | 只在 `feat/modular-platform` 做；壳改动可择机 cherry-pick |
| 模式 A 漏依赖导致客户包跑不起来 | MANIFEST + 导出后自动 `import`/启动冒烟 |
| 模式 B 只藏菜单、API 仍开放 | Phase 2 必须上 API 模块守卫，验收项写死 |
| 跨模块 import 导致「少拷就挂」 | lint / 检查脚本禁止 `modules/A` → `modules/B` |
| embed 丢登录态 | 接入说明 + 联调清单 |
