# 工视 · 全局看板线框与字段清单（v0.1）

> 目标：把「报工统计摘要」升级为「例外驱动的指挥界面」。  
> 数据边界：进度来自已确认报工（非 IoT）；静默/应报可结合排班。  
> 本文只定信息架构与字段，不写实现。

---

## 0. 页面目标（验收一句话）

负责人打开后 **3 秒**能回答：今天有没有红的、最该先追哪几件；**30 秒**能点进处理页。

## 2. 区块与字段

### A. 指挥条（Command Strip）

| 字段 | 说明 | 来源口径 |
|------|------|----------|
| `red.count` | 逾期订单数 | `days_to_due < 0` |
| `red.headline` | 最紧急 1 单摘要 | 逾期中 `days_to_due` 最小的：订单号+产品+责任人 |
| `yellow.count` | 风险单数 | 临期（0～near_days）**或** 在制静默超阈值 |
| `yellow.headline` | 一句风险说明 | 如「2 临期 · 3 静默超 1 班」 |
| `green.count` | 正常在制数 | 有报工、未完工、非红非黄 |
| `green.headline` | 今日报工是否达标 | 如「报工率 72%（目标 80%）」 |
| `near_days` | 临期窗口 | 默认 3，可配置 |

交互：点色块 → 滚动/过滤到 C 或 E 对应列表。

---

### B. 今日必办（Action Queue，≤5）

每条事件：

| 字段 | 说明 |
|------|------|
| `id` | 事件 id |
| `level` | `error` / `warning` / `info` |
| `type` | 见 §3 事件类型枚举 |
| `title` | 短标题，如「应报未报」 |
| `object_label` | 人/订单/工单/产品 |
| `age_minutes` | 已挂多久（分钟） |
| `age_label` | 展示用，如「40 分钟」「1.5 班」 |
| `suggested_action` | 催报 / 去确认 / 改确认 / 跟交期 |
| `link` | 跳转路径 + 可选 query |
| `owner_role` | `director` 主任 / `lead` 班长 / `manager` 负责人（展示用） |

排序：level 红>黄>蓝，同级按 `age_minutes` 降序。  
超过 5 条进 F。

---

### C. 交期驾驶舱（OTIF-lite）

**分桶**

| 字段 | 说明 |
|------|------|
| `bucket.overdue` | 逾期单数 |
| `bucket.d3` | 0～3 天 |
| `bucket.d7` | 4～7 天 |
| `bucket.later` | >7 天或无交期单独计 |

**列表行（逾期 + 临期合并，默认 Top 8）**

| 字段 | 说明 |
|------|------|
| `order_code` / `order_name` | 订单 |
| `product` | 产品 |
| `due_date` / `days_to_due` | 交期 |
| `plan_qty` | 计划量（工单/订单计划；无则空） |
| `done_qty` | 已确认产量（订单上卷或末道相关，口径见实现注） |
| `progress_pct` | `done/plan`，无 plan 则不展示条，只显示 done |
| `behind` | 布尔：临期或逾期且 progress 低于阈值（如 &lt;70%） |
| `current_process` / `current_holder` | 最近工序/人 |
| `silent_hours` | 距最近一次已确认报工的小时数 |
| `risk_tag` | `逾期` / `临期` / `静默` / `落后` |

**卡片/行字段**

| 字段 | 说明 |
|------|------|
| `id` | wo:… / product:… |

| `product` | 产品 |
| `current_process` | 当前工序 |
| `current_holder` | 人 |
| `equipment_name` | 机（最近确认报工） |
| `total_confirmed_qty` | 已确认量 |

## 3. 事件类型枚举（轻量 Andon）

| type | level 默认 | 触发条件（首版建议） | 建议动作 | link |
|------|------------|----------------------|----------|------|
| `order_overdue` | error | 订单 days_to_due &lt; 0 | 跟交期 | /analysis?focus=order&id=…（下钻抽屉） |
| `wip_silent` | warning | 在制且 silent_hours ≥ 一个班次时长（如 8h，可配） | 查卡点 | /cockpit 定位卡片 |
| `unreported` | warning | 今日应报未报人日 | 催报 | /daily |
| `pending_timeout` | warning | 待确认且提交已超过 N 小时（如 2h） | 去确认 | /daily?status=pending |
| `rejected_open` | error | 存在驳回未处理（首版：有 rejected 即计） | 督促重报 | /daily?status=rejected |
| `finished_pending` | info | 有末道建议且未成品确认 | 确认成品 | /daily |
| `order_near_behind` | warning | 临期且 progress_pct 有值且 &lt; 阈值 | 加催 | /analysis?focus=order&id=… |

进度下钻（2026-11）：`GET /shop-floor-reports/progress/detail?scope=order|work_order|product&id=` → 摘要 KPI + 按日/班/设备/人透视 + 明细行（日–班–设备–人–工序）。进度分析点行或看板「去处理」可打开抽屉。

配置项（租户级即可）：`near_days`、`silent_hours`、`pending_timeout_hours`、`progress_behind_pct`、`attendance_target_rate`。

## 9. 报工归属、下班宽限与历史补报（统计口径）

### 9.1 日期归属（`work_date` = 班次归属日）

产量/工时/应报一律挂 **排班日**，不跟墙上时钟的自然日硬切。

| 班次 | 实际跨度（例） | `work_date` |
|------|----------------|-------------|
| 白班 | 12 日 08:00–16:00 | 12 日 |
| 中班 | 12 日 16:00–次日 00:00 | 12 日 |
| 夜班 | 12 日 00:00–08:00（或跨日早班挂牌） | 仍跟排班日 |

跨零点不把产量拆到第二天。「看 12 日全天」= 12 日白+中+夜合计。

### 9.2 下班宽限（默认 30 分钟，租户可改）

- 配置项：`off_shift_grace_minutes`，默认 **30**。  
- 班次计划结束后进入宽限；宽限内提前/延后交班都正常，**不计入「应报未报」**。  
- 宽限结束后仍无任何报工（待确认/已确认均算已报）→ 计入未报 / 必办。  
- **未开班**的班次：不算欠报（例：今天 16:00 时夜班未上，不进未报名单）。  
- 历史日（`work_date` < 今天）：全班次均已过催报点，按完整日结算。

### 9.3 进度统计 vs 催报

| 用途 | 口径 |
|------|------|
| 交期/进度分析 | **仅已确认**报工；按 `work_date` 聚合 |
| 应报/未报/报工率 | 有排班且非请假；**仅「已过下班+宽限」** 的人×日进催报分母 |
| 进行中班次 | 可看已报条数，但不标红未报 |

### 9.4 历史补报

- 允许对过去 `history_backfill_days` 天（默认 7）补报，标记 `is_backfill`。  
- 补报仍走待确认 → 主任确认；确认后与当日报工同等计入进度。  
- 已确认历史报工不可删改；待确认/已驳回可在补报窗口内删除后重报。

### 9.5 申请人 / 确认人（现网字段；微信绑定后期）

| 角色 | 字段 | 说明 |
|------|------|------|
| 作业人 | `person_id` / 姓名 | 实际干活的人（排班主体） |
| 申请人 | `submitted_by` / `submitted_by_user_id` | 提交报工的账号；后期绑定微信工号 |
| 确认人 | `reviewed_by` / `reviewed_by_user_id` | 确认/驳回的账号 |

**后期（本期不做）**：申请人与微信工号绑定；换机/换微信号由后台管理员重绑；离职解绑；**未绑定不可在小程序操作报工**。PC 后台可用账号登录不受此限，直至小程序上线再收紧。

## 10. 工序效率分析（进度详情 · 效率 Tab）

| 指标 | 口径 |
|------|------|
| 工序总产量 | 该工序已确认报工产量合计 |
| 工序总耗时 | 报工工时/起止折算合计（小时） |
| 实际单位耗时 | 总耗时 ÷ 产量（展示为 **分钟/件**） |
| 小时产量 | 产量 ÷ 总耗时 |
| 标准耗时 | 工序主数据 `unit_minutes`（分钟/件）；未维护则不算达成率 |
| 效率达成率 | 标准单位耗时 ÷ 实际单位耗时（例：5÷4=125%） |
| 等待 / 异常时间 | **尚未采集**，界面占位「—」，不计入生产工时 |

排序：有标准的工序按达成率**升序**（最低标「重点」）；无标准的按小时产量排后。标准只认工艺主数据，不在分析页随意改数。
