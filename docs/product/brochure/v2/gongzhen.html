先看清坏在哪，再决定修还是调

告警只说“超限了”。工诊继续回答：哪类故障、证据是否一致、未来 72 小时会不会恶化、先修还是先调参。覆盖生产机台，以及空压、泵、冷水机组等动力设备。

合同物料：设备健康分析模块（工诊） 可接现有测点 · 不依赖智排 对象：设备主管 / 维修 / 能源运行
01 · 设备运维在卡什么

工厂不缺测点，缺「证据 → 结论 → 动作」

SCADA 和告警台能看见超限，却很难支撑当班决策：备件要不要备、能不能降负荷顶一阵、要不要停机。

  • 如何提前发现并准确定位故障类型，而不是只看见红灯？
  • 如何减少意外停机，又避免欠维修、过维修？
  • 告警刷屏时，真正危险如何不被淹没？
  • 节能 / 提负荷建议和报警并存时，怎样不带病优化？
  • 机队很多时，主管如何先圈范围再下钻单机？
维护方式进阶

工诊落在「预测 + 可执行结论」这一层

响应式

坏了再修，非计划停机。

预防式

固定周期巡检保养。

状态监测

看趋势与阈值，仍缺结论包。

预测 + 诊断

工诊：原因概率、风险窗、处置步骤。

约束优化

异常未关，阻断激进调优。

可与智排合买：设备编码对齐后，高风险机少被高负荷硬排，维修窗口对照交期与班次。

02 · 给不同人的价值

同一条告警，三种岗位读法一致

设备主管

先看机队，再下钻

  • 按车间 / 类型 / 状态圈范围
  • 现状健康与未来风险分口径
  • 维修窗口与负荷一眼对照
维修 / 点检

结论包能照着做

  • 结论 + 证据 + 原因概率
  • 处置步骤与备件提示
  • 事件关闭后才谈优化
能源 / 运行

先稳定，再节能

  • 异常未关闭时阻断激进调优
  • 负荷 / 平衡建议带设备约束
  • 避免“越调越糟”
告警台常见读法 3# 空压机振动超限——只知道“超了”，不知道原因和下一步。
工诊读法 轴承相关概率约 62% · 72h 风险中 · 证据一致——建议降负荷 + 点检，备件提前准备。
03 · 能帮你看什么

面向旋转与动力类设备的常见故障方向

具体可诊断范围取决于测点类型与数据质量；下列为典型方向，不是承诺清单。试点时用你们的已知故障验证。

  • 电机 / 传动不对中、不平衡、松动、联轴器异常
  • 轴承磨损、损伤、润滑不良相关征兆
  • 泵 / 风机气蚀、叶轮异常、振动与电流背离
  • 空压 / 冷水负荷异常、温振耦合、能效偏离
  • 皮带 / 齿轮松紧异常、啮合磨损相关特征
  • 工况变化工艺负荷突变导致的伪故障识别

数据来源：可接 PLC / 电气 / 环境等现有测点；先接关键设备的关键测点，不必一次铺满全厂。

04 · 怎么做成

接测点 → 机队总览 → 单机证据链 → 处置闭环

测点接入振动 / 温度 / 电流 / 压力等
机队视角异常与风险先排序
单机诊断证据对照 · 原因概率
处置与约束工单 / 点检 · 阻断带病优化

不替代 SCADA / 告警采集；工诊在告警之上做解释、预测与闭环。设备离线时，预测会暂停，避免假精确。

05 · 一条时间线（示意）

空压站异响：要不要停机？

以下为产品叙事示意，便于理解闭环；正式对外请替换为脱敏试点数据。

告警出现

3# 空压机振动与峭度特征抬升

机队总览将该机标为关注；现状健康尚可，72h 风险升为中。

对照分析

振动与电流证据一致，指向轴承侧

系统给出原因概率与建议：先降负荷 + 安排点检，备件窗口提示。

现场处置

点检确认异常，按窗口安排检修

未关闭事件期间，激进节能调优被阻断，避免带病硬顶。

闭环

事件关闭，特征回落

结论与处置留痕，可供复盘与同类机对比。

结果取向：把“盯红灯猜停不停”变成“有结论、有步骤、有风险窗”——当班能定，会上能讲。
06 · 适不适合 · 怎么开始

先选一类关键设备，接一周数据验证

比较适合
  • 关键设备停机损失高
  • 已有或计划接 PLC / 电气 / 环境测点
  • 动力站与产线设备并存，需要机队视野
  • 有点检 / 维修流程可承接处置
建议先别急
  • 设备无数据且不打算接
  • 只要一个大屏，不需要处置闭环
  • 期望 AI 直接下维修指令、人不用确认
  • 关键设备少且停机损失低

上线门槛：一类关键设备 · 5～10 个可用测点 · 能承接处置的维修 / 点检流程。报价按设备类型、测点规模与上线范围沟通，可先试点。
