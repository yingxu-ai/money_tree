01 · 为什么需要智检

质量问题昂贵，往往是因为发现得太晚、证据链太散

很多工厂「有质检岗、有记录表」，但记录在纸上或分散在多个系统：过程检与成品检脱节，不合格靠口头让步，客户投诉时翻不出完整批次证据。智检要解决的是把检验嵌入生产节奏，而不是多做一个报表库。

事后判废成本高

问题流出到成品甚至客户侧，返工、召回、信誉损失远大于过程拦截。

追溯拼不齐

工单、批次、检验单、影像各管一摊，投诉来了靠人肉拼接。

处置口径不一致

隔离 / 让步 / 返工 / 报废靠经验，责任与时效说不清。

质量与计划脱节

不合格要返工，计划却不知道；放行靠打电话。

02 · 单买即可交付的价值

先把「检得清、追得到、处置得住」立住

过程 + 成品

检验嵌入工序节点，不等到最后才发现。

证据一体

数据、影像、结论与报告按批次归档。

闭环可配

不合格路径标准化，减少口头协商。

03 · 谁在用
角色典型动作
质检员按检验方案领取任务；执行过程 / 成品 / 抽样检验；录入结果与留证；发起不合格。
质量工程师 / 主管维护检验方案与判定标准；审批让步与报废；看质量看板与逃逸风险；组织追溯。
车间 / 计划接收放行或返工指令；配合隔离；在合买智排时触发返工工单与交期调整。
供应商质量（可选）来料检结果与供应商不良对比，驱动供方改进。
04 · 能力闭环

方案 → 执行 → 判定处置 → 追溯改进

检验方案→ 过程 / 成品检→ 判定与处置→ 批次追溯→ 质量改进
  • 按产品 / 工序 / 客户要求配置检验项目、抽检规则、量具与判定逻辑。
  • 检验任务与工单、批次、工序节点挂接，避免「检了但不知道是哪一单」。
  • 合格放行、不合格进入闭环；全过程保留操作者、时间与证据。
  • 看板沉淀不良模式，服务周会与客户审核。
05 · 检验方案与执行

把「检什么、怎么检、检多少」变成可执行任务

方案层

  • 过程检 / 成品检 / 来料检等类型
  • 抽样与全检策略可配
  • 项目、标准、公差、量具要求
  • 与工序模板或工单节点绑定

执行层

  • 任务领取与完成状态
  • 数值 / 合格判定 / 影像留证
  • 复检与加严抽检触发
  • 电子签名或权限确认（按企业制度）
06 · 不合格闭环（NCR）

隔离 → 评审 → 让步 / 返工 / 报废，路径清晰、责任到人

  • 隔离：防止继续流入下道或出货。
  • 评审：质量 / 工艺 / 生产会签（按企业配置）。
  • 处置：让步接收、返工、返修、报废等可配置结果。
  • 追溯：处置结论回写批次与报告，客户审核可出示。
  • 与智排合买时，返工自动形成或关联返工类工单，交期可见。
07 · 追溯与质量看板

投诉与审核到来时，证据链现成

批次追溯

从成品批次反查工单、工序检验、不合格处置、责任人与时间线。

质量看板

不良分布、逃逸风险、班组 / 供应商对比、趋势，服务管理例会。

报告归档

检验报告、影像与结论一体，减少临时拼材料。

改进输入

高频不良项反馈给智艺 / 智方 / 智规，形成跨模块改进。

08 · 典型业务场景
场景 A

关键工序过程检拦截尺寸漂移

过程检任务在机加工序后触发 → 实测超差 → 隔离在制品 → 发起 NCR → 工艺确认调机 → 复检放行；合买智艺时可对照工艺窗口是否偏移。

结果：不良停在过程，而不是堆在成品库。
场景 B

客户投诉，24 小时内出示批次证据

按出货批次反查 → 成品检与关键过程检记录、影像、判定人 → 若有让步单亦可一并出示。

结果：审核与客诉响应从「翻箱」变成「检索」。
场景 C

不合格返工打乱交期

NCR 结论为返工 → 关联智排返工工单 → 计划员重排并评估交期桶影响 → 主管看得见延误风险。

结果：质量与交期在同一事实基础上决策。
09 · 差异对比
维度纸质 / 分散表孤立 QMS 录入智检
时机事后补录多常偏成品过程 + 成品闭环
追溯难拼齐系统内可查但仍孤岛挂接工单批次 + 可回计划
处置口头有单无协同可配置闭环 + 合买重排
改进靠会议记忆报表滞后看板 + 跨模块反馈
10 · 适用自检
  • 客户或法规对批次追溯、留证要求高
  • 过程不良发现晚，成品判废与客诉压力大
  • 不合格处置口径乱，让步 / 返工责任不清
  • 希望质量结果能驱动计划放行与返工，而不是两套系统互打电话
11 · 合买协同

智检 × 智排：放行与返工进入交期与负荷视野。

智检 × 工诊：质量异常与设备健康 / 工况对照，减少误判。

智检 × 智方 / 智艺：实测反馈配方与工艺窗口。

智检 × 智规：检验作业步骤规范化、可稽核。
