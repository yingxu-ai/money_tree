01 · 为什么需要智排

车间真正的痛，往往不在「有没有甘特图」

多数工厂并不缺表格或 MES 里的排程菜单，缺的是一套懂车间规则的计划体系：人是否到岗、机是否可占、班次是否重叠、插单改完能不能回退、现场报工能不能对上计划。

智排的目标不是「再画一张漂亮的图」，而是让计划员敢改、班组长敢调、现场敢报、主管看得见风险。

交期靠人脑、插单靠吼

紧急单一来，Excel 全表重排；改完发现焊机被两个人同时占，现场才爆出来。

后果：加班赶工仍延误，客户信任透支。

人机混排、规则打架

周历里既排人又排机，或只排班组不落具体机台；多机班组被「班组互斥」误杀合理并行。

后果：计划天天改，没人信计划。

冲突要么全红要么全不管

通用排程一刀切卡死；Excel 又发现不了抢机。同班多单本可串行，却被当成硬冲突。

后果：系统不可用，又退回口头调度。

计划与现场两张皮

甘特在办公室，报工在纸上或另一个 App；偏差无人处置，排程永远「理想态」。

后果：主管看不清真实负荷与延误桶。

02 · 单买即可交付的价值

不依赖 IoT，也能先把交期与争用管住

智排可独立上线：仅凭计划占用 + 报工实绩，即可表达设备「在跑 / 空闲」（空闲 ≈ 启用且该时段无计划占用）。适合作为元启·工小智在工厂的第一块落子。

计划敢改

试排沙箱 + 影响预览 + 发布/放弃，插单不再「改死回不去」。

冲突可读

硬冲突与超载分档，贴近「同班串行」的真实习惯。

现场可追

报工签字与偏差处置同体系，计划不再停在图上。

03 · 谁在用

同一套数据，不同角色各取所需

角色典型动作
计划 / 排产员维护班制、班组、技能、设备、人员、工序模板与排班周历；建工单并按模板展开工序；发起自动排产 / 重排；管理优先级与插单。
班组长 / 调度在甘特上微调日期、班次、责任人与具体机台；处理冲突与 busy 提示；进入试排、看影响、确认后发布。
现场班组按工作日对工序开工 / 暂停 / 完工；提交日报与电子签名；反馈计划—实绩偏差。
生产主管查看交期桶、人编缺口、冲突数、计划/实绩工时；关注今日 digest（请假等）与延误风险。
04 · 能力闭环

基础数据 → 工单 → 甘特 → 报工，一条链跑通

四段各自管什么

  • 基础数据：班制（版本/生效/跨午夜）、班组、技能字典、计划侧设备台账、人员（技能与可上班次）、工序模板（标准工时、前置、设备池）、排班周历（生成、轮倒、请假替班、排班分析）。
  • 工单管理：客户订单或内部生产；优先级（含紧急插队）；类型含正常 / 返工 / 增补工序 / 返修；按模板展开工序规格后进入甘特。
  • 排产甘特：订单—工序视图；拖拽编辑；自动排产与多策略重排；试排沙箱；冲突与负荷提示；设备自动落机。
  • 工序报工：工作日视图；开工暂停完工；日报与签名；偏差处置（独立权限）。
05 · 核心差异：人机分层

周历管人，模板管池，甘特落机 —— 绝不混在一张表里硬排

这是智排相对「Excel 一张总表」和「黑盒排程」最关键的产品原则：每一层职责清晰，冲突才判得准，现场才调得动。

层级管什么明确不管什么
排班周历人是否到岗（白/中/夜、请假、替班）不在周历里指定机台
工序模板技能要求 + 可用设备池不在模板阶段锁死某一台
甘特排产日期、班次、责任人、具体机台—
冲突引擎时间重叠上的人/机互斥与班次负荷不把「同班多单」一律当硬冲突

建厂建议顺序

班制 → 班组 → 技能 → 设备 → 人员 → 工序模板 → 排班。顺序错了，后面甘特与冲突会反复返工。

06 · 冲突引擎（贴近车间）

该红的红，该黄的黄 —— 系统才有人用

硬冲突（物理不可并行）

  • 同机、日期与班次重叠，且责任人集合不相交（两人抢一机）
  • 或无法证明可串行的同机重叠
  • 发布与 digest 可感知，计划不可「假装没有」

超载告警（允许保存）

  • 同人同机同班多单默认按串行理解
  • 按日累加 hours_per_day 超过标准班次可用工时 → overload
  • 告警但不卡死，符合「同班赶几单」的现实

其他风险分档

  • 请假仍派工、缺编、技能不符、延期等分档提示，避免「一律红灯」或「一律不管」。
  • 已选定具体设备时，不以班组互斥误杀多机班组的合理并行——以设备为准，而不是粗暴按班组锁死。
  • 时间重叠判定同时看：计划日期闭区间交集 + 班次/时段重叠（白/中/夜默认不重叠）。
07 · 计划侧智能

自动排、敢重排、能试排、可冻结

  • 多策略重排：保交期、级别优先、交期优先等；范围可限当前甘特或全部未完成。
  • 试排沙箱：进入试排 → 移动/重排影响预览 → 发布或放弃。插单会议里可以「先试再定」。
  • 设备自动落机：工序带设备池且未选手动时，可按当日该班次负荷最低的启用设备自动选机。
  • 历史冻结：今天以前可冻结，避免重排把已执行计划打乱。
  • 停用与引用约束：停用设备不可新占；删除设备须先清空/迁移工序引用，保证主数据干净。
08 · 现场闭环

报工不是附属功能，是计划是否可信的前提

过程可记

按工作日报工：开工 / 暂停 / 完工，状态清楚。

责任可追

日报与电子签名，谁报的、何时报的可追溯。

偏差可处置

计划—实绩偏差独立权限处置，形成改进输入。

主管可看见

订单汇总：交期桶、人编缺口、冲突、计划/实绩工时。

09 · 典型业务场景

销售与实施可直接对照客户故事

场景 A

紧急插单，又不想把整周计划改崩

客户加急单插入高优先级。计划员进入试排，按「级别优先」重排未完成工序，查看对既有交期的影响预览；班组长确认机台与责任人后发布。放弃则回到发布前状态。

结果：插单有路径、有后果、可回退，会议能拍板。
场景 B

焊机争用：两人抢一机 vs 同人串行多单

两道焊接工序落在同一焊机同一班次。若责任人不同 → 硬冲突标红；若同一人赶两单 → 按串行累加工时，超班则 overload 告警，允许继续调日期或换池内其他焊机。

结果：系统规则与老师傅常识一致，不会被弃用。
场景 C

请假替班后，计划自动暴露风险

排班周历登记请假；甘特上仍派该人 → leave/staffing 类风险可见；调度改派有技能且当班的人，或调整班次。

结果：人的到岗与工序派工对齐，减少开班才发现缺人。
10 · 与常见做法的差异

不是「又一个排程」，而是车间可执行的计划系统

维度Excel / 口头调度通用排程套件智排
人机关系混在一张表常偏算法黑盒人—技能设备池—落机分层
冲突事后发现易一刀切卡死硬冲突 / 超载分档
插单全表重算改完难回退试排 + 预览 + 发布
现场另找工具常弱报工签字 + 偏差同体系
上线门槛低但不可扩展高、要改习惯可单买、规则贴近现场
11 · 适用企业自检

符合越多，智排越「立刻有感」

  • 三班倒或多班制，请假、替班频繁
  • 关键设备（焊机、机加、注塑等）争用明显，存在设备池概念
  • 插单、返工、返修多，交期压力大
  • 计划与现场之间需要可追溯的报工与偏差闭环
  • 希望先管交期与争用，设备健康可后续再上工诊
12 · 合买协同

边界清晰：智排管计划占用，不把诊断塞进甘特

智排 × 工诊：设备编码映射后，高风险机避免仍被高负荷占用；维修窗口对照交期与班次。

智排 × 智检：质检放行 / 返工结果回到工单与重排，质量不再游离在计划外。

智排 × 智规：开班、换型等规范与派工/班次绑定，标准动作进现场。
