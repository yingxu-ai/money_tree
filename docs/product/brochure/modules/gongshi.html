01 · 为什么需要工视

生产进度不透明，最直接的焦虑

订单下到车间后，做到哪一步了、卡在谁手里、能不能按期交货，往往靠打电话追问或车间主任凭记忆回答。系统里也许有工单表、Excel 里也许有产量，但我们要的不是「再多一张表」，而是几秒内的结论。

追问成本高

负责人一问交期，主任要找班长、班长要喊工人；信息层层转述，口径还不统一。

后果：决策慢半拍，客户电话不敢接。

卡点看不见

人没报、报了没审、末道产量没确认，进度「停了」却没人发现。

后果：拖到临期才加班，质量与成本双崩。

报工两张皮

纸质日报、微信群截图、口头报数；统计靠月底汇总，无法支撑当日调度。

后果：产量心里没底，奖金与考核难落地。

上大系统门槛高

完整 MES / IoT 采集贵、改造周期长，「看得见进度」的需求被一起吓退。

后果：继续靠吼，问题年年一样。

02 · 单买即可交付的价值

不依赖设备联网，也能先把「进度」立住

工视抓住一件事：用人报工 + 主任确认 + 成品确认形成可信进度，再浓缩成扫一眼就能看明白的全局看板。设备健康、精密排产可以以后再上；今天先解决「看不见」。

几秒看清风险

逾期 / 临期 / 正常一屏分色；异常待办直接跳到该处理的地方。电脑、手机都能看。

当下谁在做

在制清单看清：工单、工序、人、机、已确认量、距交期。

现场敢报、主任敢审

工人微信小程序报工；主任可驳回写原因；成品建议量可改（含半件）。

以前

  • 提问交期 → 打电话
  • 主任凭记忆报「差不多」
  • 月底才知道产量对不对
  • 驳回靠口头，工人不知道错在哪
→

上工视之后

  • 打开全局看板 → 红黄立见
  • 在制表告诉你人、机、工序
  • 当日应报 / 已报 / 成品有数
  • 驳回写原因，改正可追溯
03 · 全局看板长什么样

首屏只回答三句话

整体能不能按期？现在卡在哪？该追谁？ 看板是结论层；每日报工与进度分析是证据层。不在看板上堆录入，避免又变成「大表」。

04 · 能力闭环

基础信息 → 每日报工 → 成品确认 → 看板 / 分析

现场为什么愿意用

  • 下班提交：电脑或微信小程序均可；一人多行；挂工单或产品；工序/设备可选可写；时段默认带出班次。
  • 主任审核：确认 / 驳回；驳回必须写原因，表格可见「驳回原因」。
  • 成品不瞎填：按产品工艺末道工序给出建议量；没有建议时默认 0，有权限的人可手工确认。
  • 权限可拆：查看 / 报工 / 确认分权，按钮级控制，只看不审也能开账号。
05 · 谁在用

同一套进度，不同角色各取一层

角色典型动作价值
厂长 / 负责人 打开全局看板：交期风险、在制、异常 少打电话，先抓红单
生产主管 / 计划 进度分析按订单/工单看产量与交期；下钻未报与待审 跟单有据，插单有底
车间主任 每日报工确认/驳回；成品确认；盯应报未报 班组可控，责任可追
现场作业人 微信小程序下班报工：工序、设备、数量；看驳回原因改正 不用回办公室，机旁就能报
06 · 手机与小程序

工人在机旁报，负责人在路上也能看

最怕「系统只在办公室电脑里」。工视把报和看都放到手机上：现场用微信，管理用手机浏览器或同账号登录，进度不掉线。

工人 · 微信小程序报工

下班扫码即可提交：挂工单/产品、填工序与设备、带入班次时段。不用装 App、不用抢电脑。

驳回原因小程序可见，改完再报，少跑一趟办公室。

厂长 / 主任 · 手机看进度

全局看板、异常待办、在制人机，手机竖屏也能扫完。出差或外出时先看红单，再决定要不要打电话。

与电脑端同一套数据、同一套权限，不是另做一张「简化假表」。

07 · 典型场景

这些瞬间，工视最「有感」

周一早会 · 厂长

「今天哪些单会爆？」

看板逾期/临期列表 + 在制责任人，会议五分钟对齐追谁，而不是半小时打电话。手机也能先扫一眼。

机旁 · 工人

「下班了，电脑在办公室」

微信小程序直接报：挂工单、填数量、带班次时段。驳回了小程序里看得见原因，改完再交。

晚班交接 · 主任

「谁没报？哪条要驳？」

应报未报名单、待确认队列、驳回原因留痕；交接班不再靠群聊翻记录。

跨天半件 · 成品入库

「昨天机加完一半，今天怎么算？」

末道建议量可含小数；主任确认成品数，避免「每天手填成品」的假准。

08 · 差异对比

不是再买一个看板大屏

维度Excel / 微信群通用 BI 大屏工视
数据从哪来手工誊、截图常要先接数仓 / IoT现场报工确认即进度
怎么用追问好看但难下钻处理风险 → 卡点 → 动作
应报逻辑无少见有排班才应报
成品口径月底扯皮指标常粗末道建议 + 人工确认
上线门槛低但不扩展高可单买，不依赖 IoT
手机群聊截图常仅大屏小程序报工 + 手机看板

诚实边界

工视首版进度来自报工确认，不是机台实时采集。「还有多久做完」用距交期天数 + 当前工序/已产量表达；接了工诊或智排后，可再叠加真实运行与计划占用。

09 · 适用企业自检

符合越多，工视越「立刻有感」

  • 厂长或生产负责人经常被客户催交期，却说不清车间真实进度
  • 多品种、小批量，订单/工单并行，靠记忆跟不过来
  • 已有班组、班次概念，希望「有排班才算应报」
  • 工人习惯用微信，不愿先学一套复杂电脑系统
  • 暂时上不起完整 MES / 设备联网，但愿意先规范报工
  • 希望先试用见效，再决定正式付款
10 · 怎么合作

先用三个月，好用了再付款

最怕「交了钱才发现工人不用、负责人不看」。工视用先落地、后买单降低决策风险：三个月里把报工、审核、看板跑顺；觉得值，再付款续用；觉得不值，及时止损。

① 开通试用

约好账号与班组，工人开小程序，厂长开手机看板，当天就能报第一笔。

② 三个月真跑

按真实订单与交期使用；我们陪跑口径（应报、驳回、成品），不是演示点几下就走。

③ 好用再付款

交期追得上、班组用得动，再签正式付费；不好用，不强留。

说人话：不是「先付年费再学系统」，而是「先让车间用起来——打电话少了、红单看得见了，再谈付钱」。

试用期内你得到什么：全局看板（含手机）· 微信小程序报工 · 主任审核与成品确认 · 进度分析 · 基础权限。

后续可加深：习惯工视「看得见」之后，需要「排得清」再合买智排；设备健康可再上工诊。模块可分可合，不绑架一次买全。

一句话承诺

用三个月验证：工人报不报得动、负责人看不看得见、交期追不追得上——好用再付款。
