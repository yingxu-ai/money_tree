01 · 你是不是也这样

配方是核心资产，却常常只活在个人笔记本里

配方一变，成本、质量、工艺窗口、交期和供应都会跟着变；没有版本和约束，优化就变成赌博。

交接

经验不可交接

关键比例和“手感”在老师傅脑中，人员流动即资产流失。

→ 配方版本化，签核人可追溯
解释

优化不可解释

试错靠感觉，评审会上说不清为什么改、风险在哪。

→ 给调整方向、预期影响和风险
切换

试验方 / 量产方混用

现场拿到的不是当前有效版本，口头通知容易漏。

→ 状态机管切换，非量产方不能默认下发

03 · 三个关键差异

没有治理的优化，只是更危险的试错

配方优化不是算一版比例，而是让每次变更都能解释、能签核、能回滚。

版本资产化签核后切换
版本

每次量产都可追溯

追溯到版本、签核人与切换时间；历史版本冻结可查，不靠邮件和口头。

优化

约束下可解释

不是黑盒给一个神秘比例，而是给调整方向、幅度、预期收益和主要风险。

切换

状态机管住现场

非量产方不能默认下发；量产切换需签核，可快速回滚到上一冻结版本。

04 · 一个具体场景

原料涨价，质量不能掉，怎么降本

从“拍脑袋换料”到“有边界、有证据、可回滚”。

09:00

设目标

成本下降 3%，关键性能不低于现标准。

09:30

看建议

系统给调整方向：助剂 -0.3%、回料 +2%，标注风险。

10:00

小试验证

试验批上线，智检加密检验，结果回写版本。

次日

签核切换

结果达标，签核切量产 v3.3；旧版冻结可回滚。

以前老师傅凭经验换料，质量波动说不清；出了问题再改回去，批次已经流出。
现在先在约束内算，再小试验证，签核后切换；每一步有证据、可回滚。

以上为示例场景，配方与数据为示意；实际效果以试点数据为准。

05 · 适不适合你

先看配方是不是核心资产

配方稳定、无人交接、无需审计的厂，不一定要上。

通常会比较适合

  • 配方对成本 / 质量影响大，经常调整
  • 关键人员依赖强，交接 / 审计压力大
  • 优化建议要能上会、签核、回滚
  • 需要和质检 / 工艺 / 计划闭环
  • 多牌号 / 多客户配方，版本容易混

建议先别急

  • 配方固定多年不变，也不需审计
  • 没有配方 / 工艺数据，也不打算沉淀
  • 只想算一版比例，不需要版本和签核
  • 危化 / 法规行业，但没有合规负责人参与
  • 期望 AI 直接定配方、人不用验证
上线门槛

至少要有：现行配方与组分、成本 / 质量约束、能参与签核的人。

不符合不代表永远不能用，但先选 1–2 个代表配方试点更稳。

06 · 怎么开始

先在一个配方上，做一次小试

选一个成本压力大、质量稳定的配方，建版本、设约束、跑一次真实小试。

试点三步

  1. 选一个代表配方成本压力大、质量稳定、可验证的那个。
  2. 建版本 + 设约束组分、比例、成本、性能、供应、禁用清单。
  3. 跑一次小试 + 评审看建议是否可解释、试验是否达标、能否签核切换。
部署云端开通（SaaS），或本地部署
终端研发 / 工艺用电脑；审批在同一平台完成
数据账号、组织、权限随平台
服务上线培训 + 使用答疑

试点前，你只需要准备这些

  • 现行配方与组分比例
  • 成本构成与关键原料供应
  • 关键质量 / 性能指标
  • 历史试验批与质检结果
  • 配方签核与切换流程

配方数据敏感，权限和部署方式试点前先确认；建议从非核心牌号开始。

价

怎么报价：按配方数量、用户数和上线范围沟通；可以先选 1–2 个配方试点，再决定扩展。具体功能、交付范围与报价以合同为准。

07 · 常见问题

你可能还会问

和 Excel 配方表有什么区别？

Excel 存的是数；智方管的是版本、约束、签核、回滚和试验回写，每次量产都能追溯到签核人。

优化是黑盒吗？

不是。给调整方向、幅度、预期影响和主要风险，研发和评审能讨论后再决定。

试验失败怎么办？

版本保留，回到上一量产方；试验数据留档，下一轮不重复踩坑。

能管多少配方？

按产品 / 牌号 / 客户组织；具体范围和权限试点前确认。

多久能上线、多少钱？

取决于配方数量和数据完整度；按配方数、用户数和上线范围沟通，先试点再决定。

需要准备什么数据？

现行配方、组分比例、成本、关键质量指标、历史试验记录。
