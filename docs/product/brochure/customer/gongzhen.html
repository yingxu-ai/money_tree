01 · 你是不是也这样

工厂不缺测点，缺“证据 → 结论 → 动作”

SCADA 和告警台能说“超限了”，却很难说清是哪类故障、会不会恶化、该先修还是先调、备件怎么准备。

停机

坏了才知道

非计划停机打乱交期，备件被动采购，产能承诺失信。

→ 未来风险与 RUL 分口径可见
噪声

告警刷屏，真正危险被淹没

红黄绿太多，值班人员疲劳；最后变成“看到红再说”。

→ 结论 + 证据 + 原因概率，而不是堆测点
优化

建议不敢用

节能 / 提负荷建议和报警并存，怕越调越糟。

→ 异常未关闭时，阻断激进调优

03 · 三个关键差异

从“看见超限”到“能开会决策”

告警是起点，不是结论；工诊给的是能讨论、能执行的结论包。

现状健康未来风险 · 分口径
输出

不是告警列表，是结论包

结论、证据、原因概率、处置步骤放在一起；值班和维修能照着做，也能上会。

时间

现状与未来分开看

不揉成一个红黄绿；24h / 72h / 7d 风险分开，避免“今天没事”掩盖明天的事。

优化

先安全稳定，再谈节能

报警未关闭，阻断激进调优；优化建议必须过设备状态约束，避免带病优化。

同一条告警，两种读法
告警台3# 空压机振动超限

只知道“超了”，不知道原因和下一步。

工诊轴承概率 62% · 72h 风险中

证据一致；建议降负荷 + 点检，备件提前准备。

05 · 适不适合你

先看数据、设备和维修流程

没有测点和处置流程，诊断落不了地。

通常会比较适合

  • 关键设备停机损失高，备件 / 维修被动
  • 动力站与产线设备并存，需要机队视野
  • 已有或计划接 PLC / 电气 / 环境测点
  • 想从“看报警”升级到“可解释诊断 + 约束优化”
  • 多车间 / 多工厂，需要按组织范围授权

建议先别急

  • 设备没有任何数据，也不打算接
  • 只想看一个总览大屏，不需要处置闭环
  • 期望 AI 直接下维修指令、人不用确认
  • 关键设备少且停机损失低
  • 没有点检 / 维修流程可以承接
上线门槛

至少要有：一类关键设备、5–10 个可用测点、能承接处置的维修 / 点检流程。

不符合不代表永远不能用，但先选一类关键设备试点更稳。

06 · 怎么开始

先在一类设备上，接一周数据

选停机损失最高的一类设备，接 5–10 个测点，用已知故障验证诊断。

试点三步

  1. 选一类关键设备停机损失最高、故障重复出现的那一类。
  2. 接 5–10 个关键测点振动、温度、电流、压力等；先接能支撑诊断的，不求全。
  3. 用一周数据 + 已知故障验证看证据是否一致、误报多少、处置是否可执行。
部署云端开通（SaaS），或本地部署
终端设备主管 / 工程师用电脑；现场可用平板
数据账号、组织、权限随平台
服务上线培训 + 使用答疑

试点前，你只需要准备这些

  • 设备清单：编号、名称、类型、所属车间
  • 现有数据源与测点清单（PLC / 电气 / 环境）
  • 点检、维修、备件流程
  • 近半年故障与停机记录
  • 网络与采集边界（哪些数据能出）

测点接入范围与数据质量决定诊断效果；试点前先做一次数据可用性确认。

07 · 常见问题

你可能还会问

一定要接很多测点吗？

不用。先接关键设备的关键测点，能支撑诊断即可；不必一次铺满全厂。

和 SCADA / 告警台什么关系？

不替代采集和告警；工诊在告警之上做证据对照、原因判断、风险预测和处置闭环。

能预测剩余寿命吗？

提供多时间窗风险和 RUL 及置信；设备离线时预测会暂停，避免给出假精确。

报警没关闭，能优化吗？

不能。异常未关闭时系统会阻断激进调优，先处置再谈节能 / 负荷。

多久能上线、多少钱？

取决于测点与数据质量；按设备类型、测点规模和上线范围沟通，先试点再决定。

数据放哪？安全吗？

支持云端开通或本地部署；账号、组织、权限随平台，按部门范围授权。
