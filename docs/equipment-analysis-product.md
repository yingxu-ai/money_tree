> 更新：2026-09-04

## 0. 菜单（仅 5 项 + 1 个隐藏钻取页）

| # | 菜单名 | 路由 | 说明 |
|---|--------|------|------|
| 1 | 采集配置 | `/devices/collect` | 模拟采集源、测点、绑定设备 |
| 2 | 设备列表 | `/devices` | 按部门看设备，进单机 |
| 3 | 全局现状 | `/analysis/current` | **哪台异常/故障**（舰队）；单机 Tab 仍叫「现状」 |
| 4 | 全局风险 | `/analysis/future` | 概率、怎么防、防不住怎么办（舰队）；单机 Tab 仍叫「未来」 |
| 5 | 运行调优 | `/analysis/optimize` | 长寿命 / 高负荷 / 节能等目标下建议 |

系统管理里的 **部门 / 用户 / 角色数据范围** 沿用基座，不新建组织体系。

## 1. 采集配置

### 1.1 功能

| 要做什么 | 不做什么 |
|----------|----------|
| 定义「模拟采集源」及刷新策略 | 卖 2000 协议、真 PLC 驱动 |
| 定义测点（PLC 转速、电表 U/I/P、温湿度等） | 组态大屏 |
| 测点绑定到**设备**；设备绑定到**部门** | 独立一套组织树 |

Demo 阶段：后台定时写模拟时序；页面上可「手动触发一轮采集」便于演示。

### 1.2 布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 页头：采集配置 · 模拟数据源与测点绑定          [刷新] [+ 采集源] │
├─────────────────────────────────────────────────────────────┤
│ 说明条（info）：本系统不替代数采盒子；此处配置 Demo 模拟或将来 API 接入 │
├──────────────────────────┬──────────────────────────────────┤
│ 左栏 · 部门树（只读）      │ 右栏 · 主区                        │
│ 来自系统「部门管理」       │                                    │
│ 点击部门 → 过滤下方设备    │  Tab: [采集源] [测点] [设备绑定]      │
│ 宽度 ~240px               │                                    │
├──────────────────────────┤  ── Tab「采集源」──                  │
│                          │  表格：名称 | 类型(模拟) | 间隔 | 启用 │
│                          │  行操作：编辑 / 启停                  │
│                          │                                    │
│                          │  ── Tab「测点」──                    │
│                          │  表格：测点编码 | 名称 | 单位 | 分类   │
│                          │        (PLC/电气/环境) | 所属采集源  │
│                          │  [+ 测点]                            │
│                          │                                    │
│                          │  ── Tab「设备绑定」──                │
│                          │  表格：设备 | 部门 | 已绑测点数 | 操作  │
│                          │  操作：配置测点（抽屉多选测点）        │
│                          │  [+ 设备] → 表单：名称、编码、部门     │
└──────────────────────────┴──────────────────────────────────┘
```

### 1.3 关键交互

- **+ 设备**：必填 `dept_id`（部门树选择，复用 `DeptTreeSelect`）。
- **配置测点**：抽屉内按分类勾选（转速、电流、温度…），保存后模拟器按剧本出数。
- **权限**：`data_scope=ORG` 的用户只能看到本部门及下级部门的设备与配置。

### 1.4 数据（最小字段）

- 采集源：`id, name, kind=simulator, interval_sec, enabled`
- 测点：`id, source_id, code, name, unit, category(plc|elec|env)`
- 设备：`id, code, name, dept_id, point_ids[]`

## 2. 设备列表

### 2.1 功能

全厂/本部门设备的**唯一入口列表**：看状态摘要，点进单机做深入分析。

列表上的 **状态** 由「现状分析」规则汇总，不在本页手工改。

### 2.2 布局

```text

│ 页头：设备列表 · 按部门查看运行与风险摘要                      │

├─────────────────────────────────────────────────────────────┤
│ 筛选栏：[部门树选择] [状态▼全部/异常/关注/正常] [关键字搜索]    │
├─────────────────────────────────────────────────────────────┤
│ 表格                                                         │
│  设备名(链) | 部门 | 运行状态 | 分析状态 | 关键实时值 | 一行摘要 │
│  2#压缩机   | 动力 | 告警     | 异常     | 92℃/168kW | 振动温升… │
│  …                                                          │
│  行操作：[现状] [未来] [调优]  （分别链到 /devices/:id?tab=…）   │
├─────────────────────────────────────────────────────────────┤
│ 分页                                                         │
└─────────────────────────────────────────────────────────────┘
```

部门筛选与现状/未来页一致：选父部门含下级；KPI 与表格数据由后端按 `dept_id` 子树过滤，分析状态/关键字仍在客户端二次筛选。

### 2.3 列说明

| 列 | 含义 |
|----|------|
| 运行状态 | 采集中/停机/告警等（来自 PLC 或模拟状态字） |
| **分析状态** | **正常 / 关注 / 异常**（现状规则输出，见 §3） |
| 关键实时值 | 可配置 1～2 个测点，如转速+功率 |
| 一行摘要 | 例如「振动偏高，疑似机械维」 |

### 2.4 跳转

- 设备名 → `/devices/:id`（默认 Tab「概况」）
- 行操作 → 同一单机页对应 Tab

## 3. 现状分析

> **设备运行驾驶舱**：从设备规模、采集在线、运行状态、健康状态、设备类型及组织维度，对当前设备运行情况进行综合分析，使管理人员在 30 秒内掌握整体状态、识别异常设备并定位问题集中区域。

### 3.1 功能定位

分 **舰队驾驶舱**（默认全量，可选部门/类型）与 **单机深潜**（钻取交互后续迭代）。

**范围筛选：** 页顶部门树 + 设备类型；选父部门含下级。KPI、图表、部门表、重点设备表全页联动。

**三维状态（不混用）：**

| 维度 | 字段 | 含义 |
|------|------|------|
| 通信 | `comm_status` | 采集是否在线（有最近采样） |
| 运行 | `run_status` → 运行/空闲/停止/故障 | PLC/工况状态 |
| 健康 | `analysis_status` | 正常 / 关注 / 异常（AI+规则） |

**判定逻辑（健康状态）：**

| 层级 | 条件 | 列表上的分析状态 |
|------|------|------------------|
| A | 已有报警/故障/停机事件 | **异常** |
| B | 短窗（如 15min～24h）相对近期正常工况明显偏离 | **异常** 或 **关注** |
| C | 多测点同向异常（如电流↑+振动↑+温升↑，环境温湿度正常） | 提高置信度 → **异常** |

全厂页 = **运行驾驶舱**：总账 KPI → 状态分布 → 部门/类型分析 → 7 日趋势 → 重点异常清单。

### 3.2 全厂页布局 `/analysis/current`

```text

├─────────────────────────────────────────────────────────────┤
│ 态势文案（范围 + 总账摘要）                                    │
├─────────────────────────────────────────────────────────────┤
│ 运行状态饼图 | 健康状态饼图 | 设备类型柱图                     │
├──────────────────────────┬──────────────────────────────────┤
```

### 3.4 与「未来分析」的边界

| 现状 | 未来 |
|------|------|
| **已经**不对或高度可疑 | **还没**以报警为主，但可能在变坏 |
| 要不要马上派人 | 要不要排窗口、备件 |

同一台设备可以：**现状正常 + 未来高风险**（列表上两个维度分别展示）。

## 5. 运行调优

### 5.1 功能

在**工艺与安全约束内**，用户**先选目标**，再给参数建议与后果测算；**默认不下发 PLC**。

### 5.2 目标（必选）

| 目标键 | 显示名 | 用户在意 |
|--------|--------|----------|
| `life` | 长寿命 | 控温升/磨损，可略牺牲产量或电耗 |
| `output` | 高负荷生产 | 保产量/负载，接受能耗与寿命风险 |
| `energy` | 节能 | 降功率/单耗，产量可小幅让步 |
| `balance` | 平衡 | 默认演示项 |

### 5.3 全厂页布局 `/analysis/optimize`

舰队页做**策略分流**，不改 PLC。推荐键由 `_recommend_opt_key` 产出（节能 / 长寿命 / 平衡 / 高负荷；异常或受限则暂不调参）。

```text
┌─────────────────────────────────────────────────────────────┐
│ 页头：运行调优 · 先看谁该改策略，再进单机看参数区间             │
│ 部门筛选（与全局风险同口径）                                    │
├─────────────────────────────────────────────────────────────┤
│ KPI：可优化候选 | 建议节能 | 建议长寿命 | 预计可降功率           │
├─────────────────────────────────────────────────────────────┤
│ 调优判断：headline / 配比 Tag / 若落地功率约降 xx kW            │
│ 本班优先调优 Top 卡（进单机 Tab「调优」）                       │
├─────────────────────────────────────────────────────────────┤
│ 图：建议策略配比（饼） | 优化机会能耗分（柱，越低越优先）         │
├─────────────────────────────────────────────────────────────┤
│ 「优化机会」表                                                  │
│  设备 | 部门 | 能耗分 | 功率 | 产量 | 建议策略 | 能耗影响 | 为何 │
│ 「暂不调参」表（截取，原因 = 异常/受限）                         │
└─────────────────────────────────────────────────────────────┘
```

### 5.4 单机 Tab「调优」

默认选中后端 `recommended_key`。对照表数字来自 `OPTIMIZE_STRATEGY_SCORE`，步骤文案来自 `OPTIMIZE_STRATEGY_COPY`。

```text
┌─────────────────────────────────────────────────────────────┐
│ AI 运行建议（decision_line）                    [推荐 xxx]    │
├─────────────────────────────────────────────────────────────┤
│ 当前运行：模式 / 产量 / 功率 / HI / 能耗分 / 转速 / 压力 / 温振 │
├─────────────────────────────────────────────────────────────┤
│ 运行策略对照表（点选行或 Radio）                                │
│  策略 | 产量 | 能耗 | 寿命损耗 | 风险     标签：推荐 / 已选     │
│  柱图：四策略产量 / 能耗 / 寿命损耗 %                          │
├──────────────────────────┬──────────────────────────────────┤
│ 若执行「已选」：为何 / 参数 / 预计功率产量 / 怎么做 │ 相对当前   │
├──────────────────────────┴──────────────────────────────────┤
│ 硬约束 · 纪律条：工艺授权后现场 HMI；本系统不下发 PLC           │
└─────────────────────────────────────────────────────────────┘
```

异常或 `eligible=false`：只展示受限原因与当前运行，不展开四策略。

## 9. 实现顺序（本分支）

1. 产品文档（本文）✓  
2. 数据模型 + 模拟采集器 + API ✓（单一 `catalog.json`，接口只投影）
